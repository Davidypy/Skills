# 信息图渲染工具与教学内容协议

`scripts/render_infographic.py` 依赖 Python、Pillow、Pygments。若已有可用运行时直接使用；如模块缺失，先寻找本地或工作区配套运行时。不要声称缺模块时已完成出图。

工具直接绘制 1814×867 PNG，不经过模型重写或缩放。代码字号 22px、行距 29px，每页最多 25 个物理行；这些是工具的默认容量，不代表所有代码在任何布局都只能放 25 行。过长单行会报错，不能裁切。最终仍需打开图片检查中文回退字形和可读性。

## 1. 建立基准与分页

将以下 `<技能目录>`、文件路径替换成实际绝对路径。在 PowerShell 中，脚本和参数路径用引号包裹。

```powershell
python '<技能目录>/scripts/render_infographic.py' plan --source 'D:/任务/program.c' --encoding utf-8-sig --name 'program.c' --out 'D:/任务/plan'
```

- `--encoding` 默认 `utf-8-sig`，可读普通 UTF-8 和带 BOM 的 UTF-8；GBK 等旧编码需显式指定，禁止替换解码错误。
- `--name` 是图片显示名；省略时取输入文件名。聊天提取的代码应提供真实名或“未命名程序.c”。
- `--pages 2` 只指定源码页数，不限制整套教学图张数。工具在固定字号的可读容量内均分连续行；不足则报错。不得传 0 或负数。
- `--code-only` 使用整页宽代码区，用于长行源码；此模式只交付代码页，另需按教学覆盖表完成逐段解析页。两张完整代码页加一张总流程图，不足以自动证明代码已讲清。
- 默认自动页数是代码容量的下限；另按 [teaching-coverage.md](teaching-coverage.md) 规划解释容量。分析内容放不下时增加页数或解析主题，不通过删代码、漏讲或缩小字号解决。
- 默认自动寻找 Windows Consolas/微软雅黑，或 Linux DejaVu Sans Mono/Noto Sans CJK；也可用 `--mono-font` 和 `--cjk-font` 提供真实字体文件。不要虚构字体可用性。

输出 `source_original.c`（原始字节副本）和 `plan.json`。后者记录哈希、物理行数、括号字符数量、字体路径、每页的 `start`/`end`。物理行按 `splitlines(keepends=True)` 定义；末尾单个换行不额外虚增一行，末尾真正空行会保留。

可以调整 plan 中各页起止行来在合适位置拆页，但必须保持从 1 到总行数连续、无重复、无遗漏，每页不超过默认容量。不要改源文件或哈希以掩盖改写。不要手改字体参数来声称工具执行了未支持的样式。

## 2. 编写教学 JSON

读取 `plan.json` 后，根据真实源码另写 UTF-8 `lesson.json`。`source_sha256` 必须从 plan 复制，`pages` 的数组顺序和数量须与 plan 相同，每页是卡片数组。代码专页不需要 lesson，但仍需另外规划教学解析页。

当前脚本的 `plan`、`lesson`、`verify` 以源码分页为单位，不自动生成教学覆盖表，也不自动规划独立解析专页。可另用本脚本的绘图类或程序化 SVG/HTML 制作所需解析图，并在交付清单中补记文件名、主题、关联行号和尺寸；不要为容纳解析图而伪造源码行段、复制源码页范围或更改基准。源码机器核验与整套教学覆盖检查分别记录。

下面是协议示例，其中哈希、源码行号、解释、引脚和数值均须按本次真实程序替换，不能照搬：

```json
{
  "source_sha256": "从 plan.json 复制真实 SHA-256",
  "pages": [[
    {"kind": "text", "title": "程序功能", "height": 125,
     "items": ["根据实际代码写核心功能；用短句说明输入、处理和输出。"]},
    {"kind": "keys", "title": "关键语句", "height": 220,
     "items": [{"start": 3, "end": 3,
       "explanation": "语句功能 → 实际执行效果；源码由工具按行自动提取。"}]},
    {"kind": "leds", "title": "端口与灯珠", "height": 174,
     "active_level": 0, "bit_order": [7,6,5,4,3,2,1,0],
     "assumption": "示例假设：低电平点亮；从左到右为 P1.7→P1.0。",
     "rows": [{"label": "按实际代码替换本状态", "value": "0x55"}]},
    {"kind": "flow", "title": "执行路径示意", "height": 258,
     "nodes": [
       {"id":"a", "label":"实际起点", "x":0.22, "y":0.18},
       {"id":"b", "label":"实际判断？", "x":0.75, "y":0.18},
       {"id":"c", "label":"实际操作", "x":0.75, "y":0.82},
       {"id":"d", "label":"返回判断", "x":0.22, "y":0.82}
     ],
     "edges": [
       {"from":"a", "to":"b"},
       {"from":"b", "to":"c", "label":"是"},
       {"from":"b", "to":"a", "label":"否"},
       {"from":"c", "to":"d"},
       {"from":"d", "to":"a"}
     ]}
  ]]
}
```

### 卡片约束

- 代码区宽 1100px，右侧教学区宽 646px；外边距 24px，栏间距 20px。右侧卡片高度之和加 `(卡片数−1)×14` 不得超过 819px。
- `text`：`items` 是短句列表，用于功能概括、硬件条件、数码管段码说明或非 LED 场景。不要机械增加 LED 图。
- `keys`：`start`/`end` 是完整源码行号（含端点）；原句自动从基准提取。选取短的关键语句，避免整段代码挤满卡片。工具不推断注解是否正确。
- `leds`：`value` 是八位端口值，可用整数或 `"0x55"` 等字符串。`bit_order` 必须是 0～7 的完整排列，`active_level` 为 0 或 1，`assumption` 必须说明已知条件或假设。工具据此计算每一灯的状态，不接受手写亮灭数组。
- `flow`：`nodes` 的 `x`、`y` 是卡片内容区的归一化中心坐标，`width`、`height` 默认 156×54px；边 `from`/`to` 引用节点 id，`label` 可写“是”“否”。按真实分支和回边安排位置。长标签、节点重叠、交叉边或双向边需视觉检查并调整坐标；默认直线布局器不会自动避让。复杂分支可用确定性 SVG 重绘，不要改成不真实的线性流程。
- 卡片文本自动按字符换行，但源代码主体保持原物理行，不自动换行。讲解引用换行只影响卡片显示，不写回原程序。
- 遇到文字或图形溢出会失败；减少重复解释、提高卡片高度或重新分页，再生成。不要把字号降到课堂难以阅读。

## 3. 渲染与校验

```powershell
python '<技能目录>/scripts/render_infographic.py' render --plan 'D:/任务/plan/plan.json' --lesson 'D:/任务/lesson.json' --out 'D:/任务/final'
python '<技能目录>/scripts/render_infographic.py' verify --manifest 'D:/任务/final/manifest.json'
```

输出按源码顺序编号的 `page-001.png` 等图片、各页 `page-001.txt` 原文、原始源码副本和 `manifest.json`。`.txt` 用 UTF-8 保存原始字符及换行；原始编码和 BOM 以 `.c` 字节副本为准。重复运行应使用本次明确的结果目录，不能把旧页文件混作本次新增页。

验证器会检查：原始字节哈希、分页范围、每页文本、重建源码逐字符一致、PNG 哈希及尺寸。它不证明 C51 可编译、不判断电路或教学语义，也不做像素 OCR。最终须逐张打开 PNG 做视觉核验，再在回复中准确说明核验范围。

另逐项复核教学覆盖表的内容确实出现在最终PNG中；不能以文件有对应页名或存在讲解JSON作为完成证据。独立解析图也要逐张核查尺寸、代码摘录、中文、箭头、电平和状态，不能被源码页的verify结果代替。

工具没有 C51 编译器或硬件仿真器。静态检查发现的问题应单独报告，不能称为已编译或已上板验证。

## 提示词交付模式

如果用户明确只要生图提示词，按 [teaching-coverage.md](teaching-coverage.md) 的可复用提示词组织，输出包含：真实文件名、原始源码附件/基准路径、源码与解释覆盖表、按讲解容量确定的总张数、页码行段、逐页分析内容、已知硬件条件与假设、1814×867 视觉规格、不可变源码要求及核验项目的完整提示词。不得只写“解释代码”而不列出实际需要解释的语句和电路主题。

把“代码必须程序化渲染，再与教学图形合成”写进提示词。纯图像生成无法保证逐字符准确时明确说明，不将一段模型生成的代码图片当成核验通过的源程序。
