# C51 教学解析要点

把源码当成行为依据；以下是易影响教学结论的检查点，不是要求每个程序都包含这些结构。

## 语句、循环与事件

- `sbit K1=P3^4;` 中的 `^` 是 C51 位地址定义语法；不能按普通表达式里的异或解释。普通表达式里的 `^` 仍是异或。
- `if(++i==5)i=1;` 先递增再比较；`if(i++==5)i=1;` 先取旧值比较。按实际初值列出必要的状态序列。
- `if/else` 的归属、独立的多个 `if`、`switch` 中是否有 `break` 都会影响一轮执行哪些分支。不能把独立判断画成互斥分支。
- `while(!K1);` 是带空循环体的忙等。若按键低有效，它通常阻塞等待释放；判断极性必须与表达式和接线相符。
- 延时后是否再次检测按键、执行功能与等待释放的先后顺序，以代码为准。没有写消抖或释放等待，就不能在流程图中补上。
- 阻塞延时/等待会影响其他轮询任务；但不能直接声称屏蔽了中断。遇到中断函数应分别画主循环和事件入口。
- 检查循环边界、类型范围、前置/后置自增和溢出；不要在未核对编译器数据模型时泛化类型宽度。
- 源码存在无法编译、未定义标识符或不确定行为时，分别说明“源码写了什么”“在何种条件下可解释为何种行为”；不编造确定运行结果。

## 端口、LED 与方向

- 用端口值推出 bit7…bit0，再结合有效电平推出灯的亮灭。十六进制值、位状态和灯珠状态必须互相一致。
- 电路未知时可标注“假设 LED 低电平点亮，图中从左到右为 P1.7→P1.0”；或者仅展示端口 0/1，不推断灯亮灭。
- “高四位/低四位”是逻辑位编号；“左/右”是图上的位置或实物位置，不能混为一谈。
- `_crol_()`、`_cror_()` 应结合实际调用参数、初值与每轮赋值分析。逻辑旋转方向并不自动等于实物流水方向。
- 流水方向需要明确灯珠位序及有效电平；对多灯花样给出真实位序列，不能画成单灯移动。
- 蜂鸣器引脚高低不一定直接对应“发声/静音”；还与有源/无源、驱动电路及频率有关。
- 数码管段码的数字含义取决于共阳/共阴、段位映射、选通方式；缺少这些条件时先展示原始段码。
- 软件空循环不能单凭代码换算成精确毫秒。需要晶振、1T/6T/12T 内核、编译器及优化信息；否则只讲延时作用或给出带条件估算。

## 解释落地

优先选择实际出现的 `sbit`、宏、类型、条件、循环、位运算、移位函数、消抖或输出语句。原句从源码复制，并标明行号。

按语义单元检查解释是否完整，不只统计源码行数。一行内连续的“输出赋值、控制位置1、控制位清0、延时、忙等、break”有不同作用，不能只解释最终“显示并锁定”。头文件、变量、程序存储区关键字、码表含义也应在它们影响理解时讲清。

有原理图时逐项核对端口位、网络名与器件引脚，再解释电平和状态。对共享数据总线，分别跟踪数据端口、使能信号和各器件已保存的数据；数码管应按实际段位映射推导亮段，并区分段选、位选和静态/动态显示。不要将一次特定电路的位序或有效电平当作所有C51项目的默认接线。

短程序在解释完整且可读时可用一张左右分栏；中长程序按连续源码分页并在对应页解释；短行且较多时可用连续双栏；长行或大量中文注释时优先宽代码页，再按教学单元增加解析页。源码分完页后，仍需依照 [teaching-coverage.md](teaching-coverage.md) 检查代码与原理图的讲解覆盖。拆页可以跨函数或块，但不能为了让某页“闭合”添加花括号。

潜在逻辑或语法问题在源码区之外的讲解/勘误卡片中单独说明，不挤占正常工作原理的解释。不要把修复后的语句放入原始代码卡片。
