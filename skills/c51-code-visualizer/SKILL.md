# C51 代码解释与教学可视化

将用户提交的完整 C51 源程序转化为面向高职《单片机应用技术》初学者的教学材料。完整展示源码、讲清代码、解释电路是分别验收的要求；不能用代码截图、注释复述或总流程图代替逐段讲解。依据实际语句解释行为，不把注释、文件名或惯用电路当作事实。

## 输入与交付范围

- 默认交付中文 PNG 信息图，1814×867 像素、横向、白底，适合插在 PPT 标题下方。默认按代码和电路的教学内容自动确定张数，不以最少图片为目标；解释放不下时主动增加解析页。用户明确指定张数或布局时优先遵循。
- 用户只要解析、提示词或规划时，仅完成该范围。制作本技能本身不意味着执行生图；没有实际代码时，不把示例或占位文字当成程序。
- 读取完整代码、程序名（如有）、图片数量、布局和已知电路条件。缺少代码必须索取代码；其他可合理推定的参数直接说明默认值并推进。未知有效电平可以带显式假设分析，也可只展示端口位状态。
- 文件名以用户给定或源代码明确标注为准；无法识别时使用“未命名程序.c”并说明是显示名，不冒称原文件名。
- 输出默认写入当前任务的独立结果目录，不向技能目录写用户作业。

## 源码不可变基准

1. 将源文件按原字节保存。聊天代码则只提取代码围栏内部的原文，保留空行、缩进和末尾换行情况，保存后建立基准。不同编码必须显式解码，禁止用替换字符吞掉错误。
2. 记录文件名、编码、SHA-256、物理行数、各行内容和括号字符数量。括号数量包含注释/字符串时只作字符审计，不等于语法检查。
3. 不改写标识符、常量、注释、运算符、括号或重复语句，不优化代码、不自动补括号。不在源码区域加入省略号。发现错误在源码区之外的讲解/勘误卡片中说明。
4. 默认保留原始行序及缩进。行号、语法着色属于显示层，不能写回源文本。Tab 可按明确的制表位展开显示，但保留原字符供核验。
5. 分页或代码双栏必须覆盖源文件每一行且仅一次，按原始顺序连续编号。代码片段在讲解区再次引用不算源码分页重复，但须明确区分。
6. 只有代码截图时，保存原图并人工核对转录，说明空格/Tab、原始编码及截图外内容无法逐字节验证；后续源码一致性检查以注明来源的转录文本为基准，不冒称与未知原文件完全一致。

## 依据程序建立教学解释

分析时读取 [references/c51-analysis.md](references/c51-analysis.md)，按实际程序梳理：

- 输入输出引脚、类型、变量初值与函数职责。
- 初始化、主循环、条件分支、阻塞循环和中断之间的真实关系。
- 表达式求值顺序、循环次数、移位/循环移位、端口数值和状态变化。
- 按键检测、消抖、再次确认、等待释放是否确实存在，以及一次按下是否可能重复触发。
- 电路已知事实、必要假设、无法由源码独自确定的部分。

每条关键解释使用“源码行号与原句 → C51语法及语句功能 → 数据/电平变化 → 电路对应与实际效果”。纯软件语句可用对后续执行的影响代替电路效果。讲清“是什么、为什么这样写、执行后发生什么”，不只是把源码注释换一种说法。每页通常承载 3～6 个相关知识点，这是单页容量建议，不是整套讲解内容的上限。

## 教学覆盖与页数规划

制作教学信息图或制图提示词时，读取 [references/teaching-coverage.md](references/teaching-coverage.md)，按以下原则规划：

1. 先按声明与数据、初始化、主循环、分支、函数等实际逻辑拆分教学单元，建立“源码行段/语句 → 需要解释的含义 → 相关电路 → 所在图片”的覆盖表。同一行含多条语句时也要分别说明；影响理解的声明、赋值、条件和控制结构均应有讲解归属。
2. 在整套 PNG 中覆盖源码实际出现的关键内容：头文件与引脚定义、变量及数据类型、数组/码表、初始化、输入采样、判断与分支、输出控制、循环/阻塞、被调用函数。没有的内容不补造；空白行和独立花括号无需机械逐行解释，但须讲清代码块归属。
3. 有原理图时沿实际连接讲清“单片机引脚 → 网络/器件引脚 → 控制条件 → 执行结果”，解释相关有效电平、位序、数据通路和控制时序。锁存器、驱动器或扫描电路应说明保持与更新关系；不能只贴原理图或写器件名称。缺失的接线标明假设。
4. 重复结构可合并讲解：完整拆解一个代表性分支/迭代，再用对照表覆盖其余条件、数据和结果差异。例如多个 case 可共用流程解释，但不能漏掉各 case 的映射、default 的去向及 break 是否可达。
5. 以覆盖表和课堂可读字号决定总张数。代码与解释能同页放清楚时同页呈现；长行代码可另设源码页，并增设带行号引用的逐段解析页。源码页的数量不等于整套教学图数量，代码专页不计作已经完成代码解释。默认说明拆分安排后直接制作，不因自主加页另行等待确认。
6. 每张解析图围绕一个明确主题，既有相关源码摘录，也有含义解释和状态/电路效果。总流程、结果表和问题纠错用于补充正常工作原理，不替代逐段解释；关键解释必须出现在图片中，不能只放在随附文字说明里。

图文容量不足时，先拆主题加页；不得为了少出图而遗漏讲解，也不得通过缩小字号或把多个主题塞在一张图中解决。

## 布局与生成

生成图片前读取 [references/rendering.md](references/rendering.md)，其中有渲染工具命令、教学 JSON 格式和分页规则。

- 白底、细边框、圆角卡片，四周安全边距 20～30px。代码蓝色主题；关键说明绿色；运行效果橙色；流程青色。没有历史图片时按本规范制作，不声称已匹配未见过的历史作品。
- 不添加额外课程总标题。代码卡片标题显示实际文件名，右侧标注“C语言（51单片机）”及页码。
- 左侧代码区通常占 55%～65%，使用等宽代码字体和支持中文的回退字体，注释绿、关键字蓝/紫、数值橙。代码与注释不得溢出、裁切或通过极小字号硬塞。
- 右侧按内容放程序功能、关键语句、硬件效果、真实流程；多页时分配到关联页面，不要求每页重复全部模块。代码过长可用代码专页加逐段解析专页；解析页标明所讲源码行号，便于来回对照。
- 优先运行本技能的 `scripts/render_infographic.py` 确定性渲染完整 PNG。它负责源码逐行读取、分页、行号、高亮、教学卡片、端口灯珠和带连接线的流程节点；教学内容由你分析后写入 JSON，工具不推断语义。
- 脚本因行宽、文字容量或布局约束拒绝时，调整分页或布局，必要时用程序化 SVG/HTML 等工具实现同样的源码基准与覆盖核验。不要截断或悄悄缩字绕过失败。
- 普通卡片、引脚、灯珠、数码管、箭头应程序化绘制，无需图像模型。仅在用户希望或内容确实需要位图插画时使用可用 imagegen 技能；它只能负责非代码素材。不能让图像模型重画源码后宣称准确。
- 用户硬性指定的张数无法同时满足源码完整、代码解释、电路解释及可读性时，说明需要的页数和原因，提出明确排版选择；不擅自删减源码或讲解。自动张数模式按完整教学内容直接增加页数。

## 核验与交付

1. 重建所有源码页的文本，逐字符对比基准，检查连续行号、无重无漏、原始结束括号和末尾换行。保留结果清单。
2. 检查程序解释、分支条件、按键行为和硬件状态；LED 电平、位序及方向必须与已知接线或标出的假设一致。
   对照教学覆盖表逐项检查：学生能否在图中找到每个教学单元的语句含义、数据变化和对应效果？发现只有源码、只有注释复述、只有总流程或只讲问题未讲正常原理时，补充解释并按需加页。源码完整性通过不代表教学覆盖通过。
3. 逐张打开最终 PNG，检查代码、中文注释、流程节点和讲解文字是否清楚，无重叠、缺字、裁切或错位；确认每张实际尺寸。
4. 区分核验范围：源码比对通过证明排版输入一致；最终像素可读性还需视觉检查。不把源码哈希或 PNG 哈希当作 OCR 或语义正确性证明。
5. 交付图片及简短说明：总张数、源码页与解析页分工、每页源码行号与讲解主题、实际尺寸、完成的核验范围、发现的源程序问题和硬件假设。提供源码基准、教学覆盖表和 `manifest.json` 链接，便于复核。
6. 若只得到提示词、代码面板或未核验草图，明确标示交付状态，不称为完整教学信息图。工具受限时说明实际限制及已完成内容。
